# DMF 적용 1차

기존 실내 공기질 프로젝트에 DMF 데이터 관리 개념을 적용한 별도 차수입니다. 기존 1차와 최종 자료를 보존합니다. DMF 적용 최종은 이 1차의 납품 묶음이며 새 개발 차수나 별도 실험이 아닙니다.

<a id="reading-level-1"></a>
## LEVEL 1 - Beginner

### LEVEL 1 · 기존 자료가 달라졌는지 확인하기

| 입력 | 처리·확인 | 범위 |
| --- | --- | --- |
| 기존 센서 코드와 측정 CSV | 해시·버전·제한 조건·감사 이력 | 로컬 자료 검증 |

기존 센서 코드와 측정 CSV를 보관하고, 파일마다 지문처럼 쓰이는 해시를 계산합니다. 버전은 자료의 변화를 잇는 기록이고 감사 이력은 수행한 동작의 기록입니다. 별도로 준비한 DMF가 필요하며 검증 실패는 확인이 필요하다는 뜻입니다. 이 자료는 새로운 공기 측정이나 안전 판정이 아닙니다.

### LEVEL 1 · 파일이 지나가는 순서

단계별 예시와 확인할 점입니다.

| 입력 | 기록 | 결과 |
| --- | --- | --- |
| 이전에 저장한 센서 코드와 CSV를 읽습니다.<br>CSV 한 행은 PC 수신 시각과 측정값을 뜻합니다. | 파일의 바이트를 보존하고 지문인 해시를 계산해 버전과 감사 이력에 연결합니다. | 보존된 파일과 목록·보고서를 열어 확인합니다.<br>해시가 다르면 파일이 같다고 판단할 수 없습니다. |

v1은 원본 세 파일과 처리 규칙을 봉인하고 v2는 그 원본에 CSV 분석을 추가합니다.

두 버전 기록은 이번 적용 묶음의 순서를 보여 주며 과거 프로젝트 수정 이력이 아닙니다.

고정해 확인할 정보와 바뀔 수 있는 부가 정보는 구분해야 합니다.

CSV에서 값이 비어 있으면 0으로 바꾸지 않으며, 시간 간격이 긴 구간은 측정이 연속되었다는 근거가 아닙니다.

데이터가 존재하는 행 수와 특정 값이 있는 행 수는 다를 수 있습니다.

보고서의 기준과 원문을 같이 살펴보세요.

저장된 기록은 **692,182 행**입니다. 모든 행이 분석 조건에 맞았지만 AM 센서 다섯 항목에는 각각 빈칸 295개가 있습니다. 한 칸이 빈 것은 0이라는 뜻이 아닙니다. 기록 사이가 1초보다 긴 곳도 47,462 곳이므로 계속 측정했다고 단정하지 않습니다.

## LEVEL 2 - Explorer

### LEVEL 2 · 자료와 기록이 이어지는 방식

| 입력 | 처리·확인 | 범위 |
| --- | --- | --- |
| 기존 센서 코드와 측정 CSV | 해시·버전·제한 조건·감사 이력 | 로컬 자료 검증 |

원본 파일을 보존한 뒤 해시와 버전 기록을 만들고, 제한 조건과 감사 기록을 검토합니다. 검증 단계는 원본 파일과 저장된 봉인·버전 연결을 다시 대조합니다. 측정 원문을 수정하지 않으며 검증된 파일의 범위와 센서의 정확도는 서로 다릅니다.

### LEVEL 2 · 버전과 데이터의 관계

| 구분 | 역할 |
| --- | --- |
| 원본과 봉인 | 원본 파일의 바이트와 계산된 지문을 대조합니다. |
| 버전 v1·v2 | 버전 사이의 연결과 저장된 기준을 확인합니다. |
| 고정 정보·변경 가능 정보 | 고정해 확인할 핵심 정보와 별도로 바뀔 수 있는 정보를 구분합니다. |
| 측정 분석 | 값이 있는 행을 기준으로 읽고 결측과 시간 간격을 함께 살핍니다. |

버전 연결이 맞더라도 파일이 실내 환경을 정확히 측정했는지는 별개의 문제입니다. DMF의 소스 일곱 파일은 지정 커밋의 Git blob을 해시 확인 후 메모리에서 불러오며 저 장소에 복사하지 않습니다. 원본이나 이력의 일부가 달라지면 정상 결과로 간주하지 말고 해당 파일과 실행 조건을 확인합니다.

저장 CSV의 전체 692,182 행이 유효했고 제 외 행은 0개였습니다. AM 다섯 항목은 각각 691,887개 값과 결 측 295개, DHT 두 항목은 각각 692,182개 값과 결 측 0개입니다. 인접 유효 행에서 1초를 넘는 간격은 47,462개입니다. 시각에는 시간대가 기록되지 않았습니다.

## LEVEL 3 - Practitioner

### LEVEL 3 · 준비와 실행

| 입력 | 처리·확인 | 범위 |
| --- | --- | --- |
| 기존 센서 코드와 측정 CSV | 해시·버전·제한 조건·감사 이력 | 로컬 자료 검증 |

별도 DMF 체크 아웃과 기존 최종 코드 폴더를 준비합니다. build로 자료를 생성하고 verify로 저장된 결과를 다시 확인합니다. 경로 또는 DMF 버전이 맞지 않거나 원본·봉인·이력이 바뀌면 오류를 확인합니다. 결과 파일과 종료 상태를 함께 살펴보세요.

### LEVEL 3 · 준비·실행·확인

| 순서 | 확인 사항 |
| --- | --- |
| 준비 | 기존 최종 폴더의 Arduino 코드·CSV 수집기·측정 CSV와 지정된 DMF 체크 아웃을 준비합니다. |
| 생성 | 아래 build 명령에 실제 절대 경로를 입력해 별도 출력 폴더에 기록합니다. |
| 재검증 | verify 명령과 종료 상태를 확인하고 봉인 목록·버전 이력·감사 이력·분석 및 검증 결과를 함께 읽습니다. |
| 오류 | 경로 누락, DMF 커밋·소스 불일치, 원본·봉인·버전 체인·감사 기록 불일치를 각각 확인합니다. |

```powershell
python tools/dmf_air_quality.py build --source-root "D:/2026/수요일 PBL/코드/최종" --output "D:/2026/수요일 PBL/DMF 적용/재현결과" --dmf-root "D:/2026/수요일 PBL/DMF 적용/work/DMF"
python tools/dmf_air_quality.py verify --source-root "D:/2026/수요일 PBL/코드/최종" --output "D:/2026/수요일 PBL/DMF 적용/재현결과" --dmf-root "D:/2026/수요일 PBL/DMF 적용/work/DMF"
```

위 명령은 이 작업 환경의 경로 예시이며 자료 폴더에서 실행합니다.

다른 환경에서는 각 경로를 바꾸고 공백이 있는 경로를 따옴표로 감쌉니다. build는 이미 존재하는 출력 폴더를 덮어 쓰지 않으므로 새 경로를 사용합니다.

분석 결과의 분모와 결측값, 시각 간격을 확인하고 원본 CSV를 직접 열어 결과의 범위를 대조합니다.

원본 파일을 수정해 오류를 감추지 않습니다.

생성된 분석 결과는 전체·유효 692,182 행, 제외 0 행을 기록합니다.

AM 다섯 값은 각 691,887개이며 결 측은 각 295개입니다.

첫·마지막 기록은 파일 순서로 2026-10-03 00:29:31과 2026-10-14 14:44:49입니다.

시각 역행과 인접 동일 시각은 각각 0건, 1초 초과 간격은 47,462건입니다.

각 수치와 단위는 분석 JSON과 원문을 확인하세요.

## LEVEL 4 - Advanced

### LEVEL 4 · 구현 경계와 실패 처리

| 입력 | 처리·확인 | 범위 |
| --- | --- | --- |
| 기존 센서 코드와 측정 CSV | 해시·버전·제한 조건·감사 이력 | 로컬 자료 검증 |

도구는 고정된 DMF 체크아웃과 필요한 소스의 해시를 검사하고 별도 어댑터로 제한 조건과 감사 이력을 확인합니다. 저장 루트, 봉인과 버전 체인을 각각 다시 확인합니다. 센서 수집기 변경이나 서버·데이터베이스 구현과 분리된 로컬 작업입니다.

### LEVEL 4 · 상태와 검증 경계

| 검증 대상 | 상태와 실패 조건 |
| --- | --- |
| 외부 구현 | 고정 커밋과 일곱 Git blob의 해시가 맞아야 지정된 코드를 메모리에서 읽습니다. |
| 원본·봉인 | 보존한 원문과 봉인의 해시가 일치해야 합니다. |
| 버전 v1·v2 | 저장 루트·seal 및 버전 간 연결을 다시 대조합니다. |
| 감사 이력 | 항목의 형식과 개수를 검사해 빈 기록이 정상 이력으로 간주되지 않게 합니다. |

고정 핵심과 변경 가능한 메타데이터는 같은 보증 범위를 갖지 않습니다. 제한 조건은 DMF의 버전 생성이 자동으로 실행한다고 가정하지 않고 별도로 확인합니다. CSV의 결 측과 시간 간격은 입력 상태를 설명하며 이를 보정해 새로운 관측을 만들지 않습니다.

이번 결과의 v1·v2는 동일 문서의 두 버전이며 감사 항목은 2개입니다. 기록 692,182 행이 모두 분석에 포함되었으나 AM 다섯 필드에는 각각 결 측 295개가 있습니다. 유효 행의 인접 시각 간격이 1초를 넘는 경우 47,462건을 연속 관측으로 바꾸어 해석하지 않습니다.

## LEVEL 5 - Expert

### LEVEL 5 · 재현과 검증의 경계

| 입력 | 처리·확인 | 범위 |
| --- | --- | --- |
| 기존 센서 코드와 측정 CSV | 해시·버전·제한 조건·감사 이력 | 로컬 자료 검증 |

DMF 커밋 cf550e3b2ceb0946ba89f64e43b7d6c2f5164383의 Git blob 7개를 SHA-256으로 확인한 뒤 메모리에서 불러옵니다.

작업 트리 수정은 실행에 반영되지 않습니다.

버전 체인의 저장 루트·seal·연결과 빈 감사 이력의 개수를 별도 검증합니다.

원문 바이트를 보존하며 소수 메타데이터는 문자열로 유지합니다.

이 검증은 사람이 수행하는 승인, 운영 서버 또는 공식 DMF 배포의 보증이 아닙니다.

### LEVEL 5 · 검토 범위와 근거

| 대상 | 검토 기준 | 해석 제한 |
| --- | --- | --- |
| 외부 DMF | 고정 커밋의 일곱 Git blob 원문 SHA-256 | 외부 라이선스가 확인되지 않아 소스를 재배포하지 않습니다. |
| 버전·봉인 | 저장 루트, seal, v1·v2 연결 및 제한 조건 | 생성 함수 호출만으로 제한 조건 검사가 자동 수행된다고 가정하지 않습니다. |
| 감사 기록 | 기록 형식과 기대 개수, 빈 이력 여부 | 로컬 기록은 외부 감사 기관의 보증이 아닙니다. |
| CSV 분석 | 원문, 유효값의 분모, 결측, 시간 간격 | 관측된 기록 이외의 연속성·센서 정확도는 입증하지 않습니다. |

각 결과의 숫자와 분모는 생성된 분석 결과와 보존 원문을 함께 확인합니다.

센서 통계의 Decimal 값은 문자열로 보존하므로 표현을 부동소수로 변환해 원값으로 오인하지 않습니다.

코어와 변경 가능 필드의 경계, seal 검증과 버전 연결, 별도 제한 조건 확인은 서로 다른 검사입니다.

실제 실패 경로의 범위는 실행 결과 및 테스트 기록으로 대조하며 서버·DB·사람 승인 기능을 주장하지 않습니다.

분석 JSON의 전체·유효 행은 각각 692,182, 제외는 0입니다.

DHT 두 필드의 유효 값은 각 692,182, AM 다섯 필 드는 각 691,887이며 각 결 측은 295입니다.

유효 행의 인접 시각 역행·동일은 각각 0, 1초 초과 간격은 47,462입니다.

Arduino 규칙 재현 등급은 좋음 30·보통 165·나쁨 96·매우 나쁨 691,891 행이며 분모는 유효 행 692,182입니다.

공인 안전 판정이 아닙니다.

## 사용과 자료

| 단계 | 명령 또는 자료 |
| --- | --- |
| 생성 | `python tools/dmf_air_quality.py build --source-root <원본코드최종> --output <본차수/실행결과> --dmf-root <별도DMFcheckout>` |
| 재검증 | `python tools/dmf_air_quality.py verify --source-root <원본코드최종> --output <본차수/실행결과> --dmf-root <별도DMFcheckout>` |
| 입력 | 기존 Arduino 센서 코드, Python CSV 수집기와 측정 CSV |
| 출력 | 원본 보존 파일, 봉인 _목록·처리 _규칙·버전 _이력·감사 _이력·모듈 _증명·분석 _결과·검증 _결과·파일 _무결성 JSON과 Markdown·HTML 적용 보고서 |

명령은 [자료 폴더](../../DMF%20적용/1차)의 도구 경로를 기준으로 실행합니다.

외부 [DMF 저장소](https://github.com/leecursion/DMF)는 별도로 준비하며 DMF 원본 코드는 이 저장소에 재배포하지 않습니다.

기존 측정 데이터는 과거 기록으로 해석해야 하며, 파일 무결성은 센서 정확도나 의료·환경 안전을 증명하지 않습니다.
